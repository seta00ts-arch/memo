# しおり（仮称） — 個人用記事保存・メモアプリ

Web記事の保存、日常のメモ、複数資料のまとめを一か所で扱う個人用ノートアプリの試作版です。
仕様の詳細は [`docs/shiori_specification_v0.1.docx`](./docs/shiori_specification_v0.1.docx)
（本仕様書）を参照してください。本READMEはその仕様に対する実装状況を、仕様書と同じ言葉づかいで
区別して示します。

「実装済み」は動作保証や実機検証済みを意味しません。

## 技術構成

- React + TypeScript + Vite
- ローカル保存: IndexedDB（`idb`）
- 状態管理: Zustand
- Markdown: `marked` + `dompurify`（サニタイズ）
- クラウド同期: pCloudまたはDropboxを選択可能。いずれもブラウザ完結のOAuth（`response_type=token`）+
  REST APIで、サーバーサイドは経由しない

## 使い方（開発）

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 型チェック + 本番ビルド
npm run lint
```

サーバーサイドは無く、静的ファイルをホスティングするだけで動作します。

## 公開（GitHub Pages）

個人利用のみを想定し、追加費用のかからないGitHub Pagesで公開する構成にしています。
`main`ブランチにpushすると `.github/workflows/deploy-pages.yml` が自動でビルド・公開します。

初回のみ、リポジトリの Settings → Pages → Source を「GitHub Actions」に設定してください
（この一回だけは手動操作が必要です）。公開後のURLは次の形になります。

```
https://<GitHubユーザー名>.github.io/memo/
```

iPhone（Safari）・Windows（Edge/Chrome）どちらからもこのURLでアクセスできます。

## クラウド同期アプリの登録（pCloud / Dropbox）

設定画面の「同期先」でpCloudかDropboxのどちらかを選べる（両方を切り替えて併用することも可能）。
pCloudは個人用アプリの承認に時間がかかることがあるため、承認待ちの間はDropboxを使う、といった
運用ができる。

### pCloudの場合

1. pCloudの開発者向けページで「自分用アプリ」を登録する。
2. アプリの **Redirect URI** に、上記の公開URL（`https://<ユーザー名>.github.io/memo/`）を設定する。
3. 発行された **Client ID** を控える（Client Secretやパスワードはこのアプリには入力しない）。
4. 「しおり」の設定画面で同期先を「pCloud」にし、Client IDを入力して「接続する」を押すと、
   pCloudの認可画面に遷移し、許可すると上記URLに戻ってブラウザ内で接続が完了する。

### Dropboxの場合

1. [Dropbox App Console](https://www.dropbox.com/developers/apps) でアプリを作成する。
   API欄は「Scoped API」、アクセス種類は **「App folder」** を選ぶ（しおり専用フォルダのみに
   アクセスが限定され、Dropbox側のフルアクセス権限を渡さずに済む）。
2. 「OAuth 2」の **Redirect URIs** に、上記の公開URLを追加する。
3. 発行された **App key**（Client ID相当）を控える（App Secretはこのアプリには入力しない）。
4. 「しおり」の設定画面で同期先を「Dropbox」にし、App keyを入力して「接続する」を押すと、
   Dropboxの認可画面に遷移し、許可すると上記URLに戻ってブラウザ内で接続が完了する。

Dropboxは「App folder」アクセスタイプでの個人利用であればアプリ審査（App Review）が不要なため、
pCloudの承認待ちの間の代替として使える。

## iPhoneの共有メニューから保存する（ショートカット経由）

iOSのSafariは、PWAが共有シートの受け取り先になる「Web Share Target API」に対応していないため、
純粋なWebアプリのまま「共有→しおりに直接渡る」機能は実現できません。代わりに、iOSの
「ショートカット」アプリを使った代替手段を用意しています。

1. 「ショートカット」アプリで新規ショートカットを作成する。
2. 「共有シートに表示」をオンにし、受け付ける種類に「URL」を含める。
3. アクションとして「URLを開く」を追加し、次のURLを設定する（`共有シート入力`はショートカットの変数）。
   ```
   https://<ユーザー名>.github.io/memo/?share_url=共有シート入力
   ```
4. Safariで記事を開き、共有ボタン→作成したショートカットを選ぶと、「しおり」が開いて
   記事保存ダイアログにURLが入った状態で起動する。

## 実装状況（2026年9月17日時点）

### 実装済み（本セッションで実装・ブラウザで動作確認済み）

- 記事の保存（URLのみ／本文貼り付けの両方、指定したノートブックまたは受信箱への保存）
- メモの作成・編集・自動保存（デバウンス方式）
- Markdown編集（見出し・太字・箇条書き・チェックリスト・リンクのツールバー、プレビュー切替）
- ノートブック・タグ・お気に入りによる整理、受信箱／すべてのノート／タグ／お気に入りの各ビュー（各ビューの意味を説明する案内文つき）
- ノートブックを開いた状態での新規メモ・記事保存は、そのノートブックに保存される
- タグ一覧・ノートブック一覧の専用ページ（件数表示、ノートブックはその場でリネーム・削除も可能）。サイドバーは一覧への入り口とスクロール式のクイックリンクのみとし、増えても縦に伸びすぎないようにしている
- タイトル・本文・出典URL・タグを横断する検索
- 添付（画像PNG/JPEG/WebP・PDF・テキスト、1ファイル20MBまでの検証）。ファイル名をタップすると
  ダウンロードせずアプリ内のビューワで画像・PDF・テキストを直接プレビューできる
  （ダウンロード自体は別のボタンから）
- ファイルからの直接ノート作成（PDF・画像・テキストを選ぶと、そのファイルを添付した新規ノートを作成）
- 出典URLを新しいタブで開くボタン
- ノート内容をクリップボードにコピー（Claude/ChatGPT等への貼り付け用。タイトル・出典URL・タグ・
  日時などのメタデータは含めず、原文・コメント・メモの内容のみをコピーする。共有・Markdown書き出しは
  従来どおりメタデータ付き）
- まとめノート（複数ノートを選択して参照元を残したまま1つのノートを作成）
- 履歴（編集のたびに版を保持し、任意の版を新しいノートとして複製できる）
- ゴミ箱（削除・復元、手動での完全削除。30日経過後の自動完全削除は下記の追加機能を参照）
- 全データの書き出し・読み込み（JSON形式のバックアップ）、個別ノートのMarkdown書き出し
- Windows想定の3カラムレイアウトと、iPhone想定の一覧⇄本文切り替えレイアウト（レスポンシブ）
- サイバーパンク2077風のダーク配色（ネオンイエロー・シアン・マゼンタ）をPC・iPhoneともに適用
- 記事保存時の重複URL検出（同じ出典URLのノートが既にあれば、開くか別版として保存するか選べる）
- iOSショートカット等からの共有URL受け取り（`?share_url=`パラメータで記事保存ダイアログを自動起動。下記「iPhoneの共有メニューから保存する」参照）
- 完全削除の同期伝播（削除マーカーをpCloudにも記録し、他端末が同じノートを再ダウンロードで復活させないようにする）
- 添付を外した後でも、外す前の履歴の版からは復元できる（添付の実体は、ノート自体を完全削除するまで消さない）
- 削除と編集の競合保護（他端末で完全削除された直後に、オフラインの端末で同じノートを編集していた場合、削除マーカーの取り込み時に編集内容を黙って失わず、新しいノートとして複製して残す）
- ノートブックのリネーム・削除の同期伝播（リネームは更新日時で新しい方を採用してマージ、削除はノートと同様に削除マーカーで他端末にも伝える）
- 自動保存と履歴スナップショットの分離（本文などの自動保存自体は都度行うが、履歴スナップショットは前回から一定時間（5分）経っていない場合は作らず、編集中に細かい版が大量にできるのを防ぐ。添付の追加・削除は離散的な操作のため、間隔に関わらず必ず版を作る）
- 記事原文と自分のコメント・メモの分離（記事保存時に「原文」と「コメント・メモ」を別々に入力でき、ノート編集画面でも原文セクション（折りたたみ可能）とコメント欄を分けて表示。検索・履歴・Markdown書き出しもそれぞれ両方に対応）
- Evernote（.enex）からのインポート（設定画面から取り込み。出典URLがあるノートは記事として原文欄に、無いノートはメモとしてコメント欄に取り込む。タグ・作成日時・添付ファイルも引き継ぐ。ENML→Markdown変換は簡易的なもので、表・下線・暗号化コンテンツなど一部の書式は失われる）
- 同期先にDropboxを追加し、pCloudと切り替えて使えるようにした（`src/lib/storageProvider.ts`の共通インターフェースに、Dropbox用実装`src/lib/dropbox.ts`を追加。Dropbox側の通信はPlaywright上でfetchをモックした仮想ファイルシステムに対して検証し、アップロード・ダウンロード・重複防止のロジックを確認した。pCloud用の実装`src/lib/pcloud.ts`はそのまま両立させている）
- 同期の競合検出ロジックを修正した。従来はアップロードをダウンロードより先に行っていたため、
  他端末の競合する編集を確認する前に自分の版でリモートを上書きしてしまい、実質的に「後から
  同期した端末が常に勝つ」状態になっていた（両方の版を残す処理が発動しない不具合）。ダウンロード
  （マージ）を先に行う順序へ変更し、さらに履歴チェーンの前後判定の向きが逆だった不具合、
  自動保存のスロットリングにより同じ履歴IDのまま内容だけが違う場合を見逃していた不具合も
  合わせて修正。2つの独立したブラウザコンテキスト（＝2台の端末を模す）で実際に競合を
  発生させ、両方の編集が失われずに残ることをPlaywrightで確認した
- ノート一覧・ノートブック一覧でのスワイプ削除（左にスワイプすると削除ボタンが現れる。タッチ・
  マウスドラッグどちらにも対応。ノートの削除はゴミ箱への移動、ノートブックの削除は既存の確認
  ダイアログ付きの削除と同じ処理を呼び出す）
- ゴミ箱の自動削除（ゴミ箱に入れてから30日経過したノートは、次回アプリを開いたときに自動で
  完全削除される。削除マーカーも作成されるため他端末にも伝わる）
- ノート一覧の「選択」モードにまとめて削除ボタンを追加（複数ノートをチェックボックスで選び、
  一括でゴミ箱へ移動できる。まとめノート作成と同じ選択UIを共用）
- 同期処理を1項目ずつの通信失敗に強くした。従来は同期中に（例えば通信の瞬断で）ノート・
  ノートブック・履歴・添付・削除マーカーのいずれか1件のアップロードやダウンロードが失敗すると、
  その回の同期処理全体がそこで止まってしまい、それ以降に残っていた項目は（エラーは出ていても）
  同期されないままになっていた。これが「一部のノートブックだけ他端末に反映される」といった
  症状として現れうる不具合だったため、各項目の送受信を個別にtry/catchで囲み、1件失敗しても
  残りの項目の同期は続行するよう修正。失敗した項目があれば同期結果に件数と内容を表示する
  （もう一度同期すれば、失敗した項目だけ自動的に再送・再取得される）
- 自動同期（アプリを開いている間、5分おきに自動で同期する。ページを開いた直後と、他のタブ・
  アプリから戻ってきたとき（visibilitychange）、オンラインに復帰したときにも同期する）。
  設定画面のチェックボックスでオン・オフを切り替えられる（既定はオン）。ブラウザのタブや
  アプリを完全に閉じている間は同期できない点は変わらない（Webアプリの仕組み上、Service
  WorkerのPeriodic Background SyncはiOS Safariなどでは使えず、プッシュ通知サーバーもないため）

## データモデル（`src/types.ts`）

- `Note`: ID・種別（記事/メモ/まとめ）・タイトル・本文（自分のコメント・メモ）・
  記事原文（任意、本文とは別フィールド）・出典URL・ノートブック・タグ・
  お気に入り・ゴミ箱状態・作成日時・更新日時・添付ID一覧・現在の履歴ID
- `Attachment`: ファイル名・形式・ファイル本体（Blob）。IDで参照されるため、履歴から複製した
  別ノートが元ノートの添付を参照することもある（実体は共有し、複製はしない）
- `HistoryEntry`: 親履歴ID・時刻・その時点のスナップショット（添付ID一覧を含む）
- `Notebook`: 名前・作成日時・更新日時（同期時のマージ判定に使用）
- `Tombstone`: 完全削除の同期伝播用マーカー（ノート／ノートブック共通、種別を`kind`で区別）

## クラウド接続について

パスワードやClient Secret（App Secret）はアプリに入力しません。設定画面で同期先
（pCloudまたはDropbox）を選び、自分用アプリのClient ID（Dropboxの場合はApp Key）のみを
入力し、表示されるURLを戻り先（Redirect URI）として登録してください。接続情報
（アクセストークン）はブラウザのセッション（`sessionStorage`、プロバイダごとに別キー）にのみ
保持し、ブラウザを閉じると再接続が必要です。

pCloudは通常の専用フォルダ（`/Shiori`）を使用しますが、フォルダ限定のAPI権限ではなく
フルアクセストークンを使用します。Dropboxは「App folder」アクセスタイプのアプリとして登録する
前提で、その場合はDropbox側の仕組みでアプリからのアクセスが専用フォルダ内に限定されます。
